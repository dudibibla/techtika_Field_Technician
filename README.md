# מסלול · מוקאפ חי

מוקאפ חי ל־Use Case 04, שיבוץ טכנאי שטח (Techtika FDE, מפגש 13).

ארבעה מסכים שאפשר ללחוץ בהם, עם נתונים בנפח של הלקוח ומצבי שגיאה:

| מסך | קובץ | למי |
| --- | --- | --- |
| תכנון מחר: לוח שיבוץ ומפה | `dispatcher.html` | משבצת במוקד |
| היום בזמן אמת: מפה ו"דורש טיפול" | `live.html` | משבצת במוקד |
| "המשימה הבאה" בנייד | `technician.html` | טכנאי וקבלן משנה |
| וואטסאפ עם זמן הגעה | `customer.html` | הלקוח בבית |

`index.html` הוא דף הפתיחה, וכתוב בו רצף ההדגמה ללקוח.

## הרצה

אין התקנה ואין build. זה HTML, CSS ו־JavaScript בלבד.

- **VS Code:** פותחים את התיקייה, מתקינים את התוסף Live Server, לוחצים קליק ימני על `index.html` ובוחרים "Open with Live Server".
- **בלי תוספים:** מריצים `npx serve .` או `python -m http.server` מתוך התיקייה, ונכנסים ל־`http://localhost:3000` או ל־`http://localhost:8000`.
- **GitHub Pages:** ב־Settings → Pages בוחרים את ענף `main` ואת תיקיית השורש. המוקאפ יעלה בכתובת של הריפו.

הגופנים נטענים מ־Google Fonts. בלי אינטרנט הדפים עדיין עובדים, עם גופן ברירת מחדל.

## מה מדומה

- **נתונים:** 24 טכנאים (18 עובדים ו־6 קבלני משנה) וכ־150 קריאות ביום, שנוצרים ב־`js/data.js` מ־seed קבוע, כך שבכל טעינה מופיע אותו יום. כל השמות, הטלפונים והכתובות בדויים. רק הקואורדינטות של הערים אמיתיות.
- **הצעת שיבוץ:** כלל greedy פשוט: כל קריאה הולכת לטכנאי המוסמך שמגיע אליה הכי מוקדם בתוך החלון. במוצר עצמו החישוב עובר ל־Google Route Optimization.
- **מפה:** SVG שמצויר מקואורדינטות, בלי מפתח API. במוצר: Google Maps JavaScript API.
- **שמירה:** אין שרת. שינויים נשמרים רק עד שמרעננים את הדף.

## איפה משנים

- כמות הקריאות: `Array.from({ length: 158 }` (מחר) ו־`{ length: 160 }` (היום) ב־`js/data.js`.
- הטכנאים וההסמכות: `TECH_ROWS` ב־`js/data.js`.
- השעה במסך "היום": `DATES.now` ב־`js/data.js` (בדקות מחצות; 640 = 10:40).
